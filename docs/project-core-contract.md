# tcm-db 项目核心契约

## 一句话身份

`tcm-db` 是一个面向中医学习、资料检索和数据整理的本地结构化知识库。它的核心价值是把公开资料沉淀为可查询、可审计、可继续维护的数据底座，而不是给出诊断、处方或治疗建议。

## 窄腰契约

无论后续 UI、RAG、导入器或部署方式如何变化，以下契约应保持稳定：

- 权威数据产物：`tcm_knowledge.db` 是当前可用数据库；在完整重建链路恢复前，不把脚本运行结果宣传为可完整复现。
- 只读优先：查询、审计和示例默认不修改数据库；写入型迁移必须有 dry-run、备份、审计和回滚证据。
- 来源可追踪：新增数据应记录来源仓库、来源路径、来源记录或可人工复核的证据；不能用不稳定标题冒充身份键。
- 安全边界：Web API 的表名、列名、文件路径和导出入口必须经过白名单或路径边界检查。
- 医疗边界：项目只支持学习和研究检索；不得输出“可直接用于个人治疗”的确定性建议。

## 柔性实现层

以下部分可以自由替换，只要不破坏窄腰契约：

- Web 页面样式、前端交互、分页方式和可视化形式。
- 搜索实现，如 LIKE、索引、外部检索或 RAG。
- 数据导入脚本的目录结构、命令名和中间文件格式。
- 测试框架和本地运行方式。
- 部署环境和端口。

## 高风险停止线

遇到以下情况应停止自动写入，先形成审计报告或人工决策：

- 无稳定来源身份键，无法保证幂等导入。
- 源数据许可、来源或版本不明确。
- 迁移会删除、合并或重写核心实体，但缺少 dry-run 和备份。
- 审计出现 hard violation、外键错误、JSON 错误或 evidence 引用断裂。
- 功能会让用户误以为系统能替代医生诊断或开方。

## 最小验收

每次维护至少保留一组可复查证据：

```bash
python3 -m unittest discover -s tests -p 'test*.py' -v
python3 scripts/audit_db.py
python3 scripts/etl.py --check
```

`scripts/audit_db.py` 的 warning 可以作为后续清洗队列；hard failure 才阻断发布。`scripts/etl.py --check` 已知会报告 clinical_cases 来源键问题，这是目前阻止自动导入的保护机制。
